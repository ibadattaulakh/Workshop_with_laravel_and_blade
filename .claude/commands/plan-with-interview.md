description: "Create a plan by interviewing the user first instead of guessing"
---

Explore [target directory/code], understand how it works, then interview me (using the Ask User Question tool) to flesh out a plan for [feature/change].

Make sure to:
1. Scan and understand the existing code/patterns first
2. Use the Ask User Question tool to ask clarifying questions
3. Collect all necessary details before planning
4. Surface important tradeoffs and decisions
5. Create a detailed plan based on the answers

Important areas to explore in the interview:
- Scope and structure (what level of detail, overview vs detail views)
- Behavior (auto-update vs manual, real-time vs on-demand)
- Location (where should this live, what routes)
- UX (what to display, how users interact)
- Actions (what actions should be available)
- Technical considerations (data sources, permissions, performance)

After collecting answers, create a comprehensive plan that:
- Matches the user's answers
- Includes all requirements
- Addresses tradeoffs
- Flags any undecided areas
- Follows existing patterns
